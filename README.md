# zerotier-macos-lan-fix
# macOS + ZeroTier：文明6局域网搜不到房间的广播路由排查与脚本

通过 ZeroTier 联机时，虚拟网络已经连接，《文明6》的局域网列表却可能仍然找不到房间。一个值得检查的原因是：发往 `255.255.255.255` 的广播，仍然从本地网络接口发出，而不是进入用于游戏的虚拟网络。

本文记录一次 Mac 上的路由排查，并分享一个自动查找虚拟接口、设置广播出口的脚本。

**验证范围：手动添加路由后，系统查询到的广播出口已从 `en0` 变为目标 `feth` 接口；本文没有抓包确认 Mac 版《文明6》的实际发包方式，也没有将“路由修改成功”视为“游戏联机已验证成功”。** 脚本经过 Bash 语法检查，其全部分支尚未完成真实网络环境测试。

## 下载与使用

下载仓库中的 [设置局域网广播.command](./设置局域网广播.command)。下载时应保存文件原始内容，不要把 GitHub 网页另存为脚本。

1. 在 ZeroTier 中加入用于游戏的网络，确认已经获得 IPv4 地址。
2. 双击脚本。
3. 如果找到多个候选接口，输入与目标 ZeroTier 网络对应的编号。只有一个候选时，脚本直接使用它。
4. 出现 `Password:` 时输入 Mac 登录密码并回车。终端不会显示密码字符。
5. 出现“验证成功”后，重新打开游戏或重新进入局域网列表测试。

脚本需要管理员权限修改路由，但不会把密码写入文件。

### 双击提示“没有正确的访问权限”

下载可能没有保留执行权限。在终端输入 `chmod +x`，后面留一个空格，再把脚本从访达拖入终端，按回车，然后重新双击。

也可以在脚本所在目录运行：

```bash
chmod +x "设置局域网广播.command"
```

或直接用 Bash 执行，不依赖文件的执行权限位：

```bash
/bin/bash "设置局域网广播.command"
```

## 问题现象与证据

Windows 上有一篇[《文明6多人局域网刷新不出房间的解决方法》](https://zhuanlan.zhihu.com/p/476795624)，作者通过调整接口跃点数，修正了广播出口。这为 Mac 上的排查提供了方向，但 Windows 的操作不能直接照搬。

在 Mac 上，查看 IPv4 路由表：

```bash
netstat -rn -f inet
```

本次排查中，与问题有关的条目如下：

```text
Destination          Gateway              Netif
10.75.160/24         link#27              feth3825
255.255.255.255      ff:ff:ff:ff:ff:ff    en0
```

这说明虚拟网段的路由存在，但有限广播地址仍走 `en0`。进一步查询：

```bash
route -n get 255.255.255.255
```

结果中出现：

```text
interface: en0
```

再检查目标虚拟接口：

```bash
ifconfig feth3825
```

关键输出是：

```text
inet 10.75.160.189 netmask 0xffffff00 broadcast 10.75.160.255
status: active
```

其中 `10.75.160.189` 是本机在虚拟网络中的地址，不是朋友电脑的地址，也不是网关。以上地址和接口名称来自一次排查，仅作为示例，使用时应读取自己电脑的当前值。

## 为什么虚拟网段能连通，不代表能发现房间？

下面几种通信需要区分：

| 目标 | 含义 |
| --- | --- |
| `10.75.160.106` | 虚拟网络中某一台设备的地址 |
| `10.75.160.255` | 本例 `/24` 网段的子网广播地址 |
| `255.255.255.255` | IPv4 有限广播地址，不编码某个特定虚拟网段 |

发给虚拟 IP 的单播可以匹配 `10.75.160.0/24` 这条路由。发给 `255.255.255.255` 的广播则不能仅凭这条网段路由决定使用同一接口。因此，即使两台设备能互相 ping 通，也不能据此判断游戏的广播发现一定正常。

ZeroTier 本身具备虚拟以太网广播能力，其协议把以太网广播作为所有成员订阅的多播组处理。但前提是相关数据已经进入虚拟网络，还要满足网络配置和流量规则。[ZeroTier 协议说明](https://docs.zerotier.com/protocol/)

原文称《文明6》使用 `255.255.255.255` 搜索房间。如果 Mac 版也使用这个目标地址，并由系统路由选择出口，那么本次观察到的出口就是一个可能的故障点。应用若自行绑定接口或采用其他发现机制，仅修改这条路由可能没有效果。

## 手动修改与验证

本次排查中，以下命令成功添加了临时路由：

```bash
sudo route -n add -host 255.255.255.255 -interface 10.75.160.189
```

这里 `-interface` 后面使用的是**本机目标接口的 IPv4 地址**。它表示通过对应接口直接到达目标，不是把本机 IP 当作普通路由器网关。

再运行：

```bash
route -n get 255.255.255.255
```

结果变为：

```text
interface: feth3825
flags: <UP,HOST,DONE,STATIC,BROADCAST>
```

这验证了系统所选出口发生变化。命令语义可以在 Mac 本机的 `man route` 中查阅。

此前尝试直接执行 `change ... -interface feth3825` 得到了 `Invalid argument`。这一错误不能推广为所有 macOS 都不接受接口名称；这里只记录本次环境中成功的做法：添加路由，并使用接口的本机 IPv4 地址。

## 脚本如何工作？

完整源码见 [设置局域网广播.command](./设置局域网广播.command)。它使用 macOS 自带的 Bash 和网络工具，无需安装额外依赖。

1. 用 `ifconfig -l` 枚举接口，筛选名称以 `feth` 加数字开头的候选。
2. 读取每个候选的状态和 `inet` 地址，只保留 `active` 且具有非 `169.254.*` IPv4 地址的条目。
3. 一个候选直接使用，多个候选由用户选择。
4. 查询 `255.255.255.255` 的当前出口。如果已经是选中的接口，直接结束。
5. 请求管理员权限，再次检查所选 IP 是否仍在该接口上，避免输入密码期间网络已切换。
6. 使用本机虚拟 IP 添加广播主机路由。如果提示 `File exists`，仅在查询到的目标路由为静态路由时尝试 `change` 更新；其他情况停止并显示错误。
7. 重新查询出口，只有与所选接口相符才报告验证成功。

**接口识别是基于名称和地址的筛选，不是通过 ZeroTier API 认证接口归属。** 其他软件也可能创建 `feth`，因此应将候选 IP 与 ZeroTier 中显示的地址核对。若当前 ZeroTier 版本使用其他接口命名方式，本脚本不会自动识别。

脚本不清空路由表，不更改默认路由，不关闭防火墙，也不安装后台服务。它会影响本机遵循这条路由的有限广播流量，不仅限于《文明6》。一次运行只选择一个广播出口，不会把广播复制到所有 ZeroTier 网络。

## 为什么换“房间”后要重新运行？

要区分游戏房间和 ZeroTier 网络：

- 只更换游戏房间或房主，但继续使用同一个虚拟网络，通常不需要重新设置。
- 更换 ZeroTier 网络后，虚拟接口和 IP 可能改变，需要重新检测。

本次排查中，接口从 `feth3825` 变为 `feth3810`，网段从 `10.75.160.0/24` 变为 `10.75.172.0/24`，随后广播查询又显示 `en0`。能够确认的是前后路由状态发生了变化，未追踪到具体由哪个网络事件删除或重建了路由。

脚本使用临时路由，不保证在重启、断开网络或接口重建后保留。它不会监听网络变化自动运行；换网络后手动运行一次即可重新检测，无需记住旧接口名和 IP。

## 撤销修改

脚本成功后会打印针对本次 IP 的撤销命令，例如：

```bash
sudo route -n delete -host 255.255.255.255 -interface 10.75.160.189
```

优先在该网络仍连接时，使用脚本打印的命令撤销。删除后重新查询路由，确认系统当前选择的出口。

如果原路由已经随着网络断开而消失，不需要继续尝试删除。若脚本更新了原有静态路由，这条撤销命令会删除更新后的路由，并不会恢复之前的自定义配置。

## 出口改对了，还是找不到房间？

继续检查双方是否加入同一个 ZeroTier 网络并得到授权、虚拟 IP 是否可达、网络是否允许广播，以及流量规则是否放行。虚拟网卡同样受到本机防火墙规则影响。[ZeroTier 官方网络配置说明](https://docs.zerotier.com/routertips/)

另外还需要检查 macOS 的游戏本地网络权限、双方防火墙、游戏版本与联机兼容性。不要把“路由正确”当成这些检查的替代品。

若要确认游戏到底向哪里发包，可以进一步抓包。示例：

```bash
sudo tcpdump -ni feth3810 'udp and dst host 255.255.255.255'
```

将接口名换成当前值，然后在游戏里刷新列表，按 `Control+C` 停止。抓到数据只能证明该接口上存在匹配的数据包；没有抓到也不能单独断定游戏未联网，它可能使用了其他地址或发现机制。

提交问题时建议提供 macOS、ZeroTier 和游戏版本，相关接口的 `ifconfig` 输出，以及修改前后的 `route -n get 255.255.255.255` 输出。公开前请去掉不必要的网络标识和设备信息。
